# Review, presentation, and documentation

## **\[20\] Sprint review**

* document:  
  * \[2\] review sprint goal and responsibilities (use 2x2 matrix)  
  * \[4\] review product backlog (by feature, then by developer)  
  * \[2\] next steps  
* etc:  
  * \[8\] **demo video (new features only)**  
  * \[4\] **Gitlab: updated issue board, sprint burndown chart**  
    * all team members commit code 

## **\[40\] Product and developer manual**

* document:  
  * \[8\] overview  
    * links to deployed app, API  
    * link to Gitlab project  
    * repo overview / structure  
  * \[8\] functional testing  
    * location of unit tests and integration tests  
    * instructions for running tests (e.g. configuration for local / deployed tests)  
  * \[8\] user testing  
    * organized by feature and then story  
    * step-by-step instructions for users to complete your stories (no screenshots needed)  
* etc.  
  * \[8\] **deployed app (we will try a few stories using your instructions)**  
  * \[8\] **Gitlab repo (up-to-date and well-organized)**

# **Presentation**

## **\[40\] Presentation**

Presentation requirements 

* presentations should take \~12 min (give or take 2 min.)  
* presentations should include slides (or another visual aid), and a pre-recorded product demo (from sprint review).

Presentation contents

* \[10\] introduction and requirements  
  * vision and value, personas
  * features and stories (selected stories only)  
* \[10\] design  
  * architecture diagram (internal or external API)  
  * API design (new features only)  
* \[10\] implementation and testing  
  * work status (done / not done)  
  * test coverage  
  * (show demo video)  
* \[10\] evaluation and conclusions  
  * accomplishments (what are you proud of)  
  * areas for improvement  
  * next steps

## Presentation peer review

Requirements:

* Review two other groups.
* If there are two presentation dates, 
  * attend both dates, and
  * review at least one presentation on the other date.

Instructions:

* Name of project you're reviewing
* Your brief summary of their app (overall) and work for this sprint.
* For each rubric section (the four above), make a few comments and try to identify:
  * something that you liked
  * something that could potentially be improved (be specific and tactful). 
* I plan to share these with the whole class.  If you don't want yours to be shared, please email Prof. Benedetto.
