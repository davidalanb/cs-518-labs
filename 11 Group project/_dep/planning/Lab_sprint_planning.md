### Planning overview

Sprint goals:

* You should have 2-3 subteams:
    * App subteam
    * API subteam(s)
* For each subteam:
    * Who are the subteam members?
    * What is/are 1-2 high-level goals?
        * e.g., app features
        * these can be identied using your user stories
* Note that the deliverables for each subteam will be:
    * Deployed App
    * Deployed API

Identifying tasks:

* Each subteam should identify specific tasks that will help them achieve their goal(s).
    * e.g., developing a route or a template for your App.
    * e.g., developing an API endpoint.
* Each subteam member should select a few tasks to start.

### Gitlab 

Sprint setup:

* Go to the group level of your project
* Go to plan > iterations
* Create a new iteration cadence - 
    * name it "sprint"
    * uncheck "enable automatic scheduling"
* click the vertical dots on the right and "add iteration"
    * name it "development" or whatever
    * start date: 04-08
    * end date: 04-28
* setup your issue board
    * stay at the group level and go to issue board 
    * create new list for the iteration you just created

Issue creation and assignment:

* select and/or create issues and add them to your new iteration.
* use labels to specify the subteam
    * optionally, you may use scoped labels, like "app::login"
* assign one (and ONLY one) team member to the tasks they will start with
    * you don't need to assign all tasks - they can be picked up as you complete tasks

Closing issues:

* When you complete an issue, you need to close it.
    - you can move it to the closed column on the issue board.
    - you can go to the issue and close it by clicking the 3 dots in the upper-right corner
